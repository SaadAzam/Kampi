### 3.2 Architecture (trust model)

| Concern | Who owns it |
|---|---|
| Match state, timers, round resolution | Realtime server (Colyseus `RpsRoom`) |
| Entry fee, payout, refund | `@kampi/domain` + PostgreSQL transactions |
| Balances shown to clients | API (read-only) |
| Player moves | Client → realtime as **intentions only** (`submit_choice`) |

Clients never compute winners, payouts, or valid-move acceptance. Chips are integers (`BigInt` in DB, strings in JSON). Wallet ledger is immutable; every financial mutation uses an idempotency key.

Match lifecycle:

```
WAITING → ACTIVE → RESOLVING → FINISHED
                       ↘ ABORTED (refund)
```

1. Player joins lobby with auth token.  
2. Two humans match immediately, or a bot fills after `BOT_FILL_AFTER_MS`.  
3. Entry fees deducted in a transaction before `ACTIVE`.  
4. Server runs rounds; choices stay hidden until both lock or timeout.  
5. Best-of-three winner gets **one** idempotent payout.  
6. Disconnect within `RECONNECT_GRACE_MS` can restore via Colyseus reconnection token.

### 3.6 Data model (Prisma / Postgres)

Enums and tables cover identity, economy, catalog, matches, progression, audit:

**Models:** User, Session, Wallet, WalletLedgerEntry, Purchase, Game, GameVersion, Match, MatchPlayer, MatchEvent, MatchmakingTicket, PlayerProgression, LeaderboardEntry, AuditLog.

**Ledger types:** STARTING_BALANCE, MATCH_ENTRY, MATCH_REFUND, MATCH_PAYOUT, PURCHASE_CREDIT, ADMIN_ADJUSTMENT.

**Purchase:** model + `PurchaseProvider` interface only (Stripe/Apple/Google/MANUAL). No live payment integration.

**Where the DB lives:** local Docker Postgres 16 (`kampi-postgres`, `localhost:5432`, db `kampi`, user `kampi`). CI uses the same image as a GitHub Actions service. Railway PostgreSQL is documented, not created.

Redis 7 is local Docker for Colyseus presence/presence-related needs.

**Clean restart (added 2 Sep, uncommitted):**

```bash
pnpm dev:reset
```

That script (`scripts/restart-dev.sh`):

1. Stops processes on 3000 / 3001 / 4000 / 2567 / 5173 and leftover `turbo run dev`  
2. Cleans `.turbo`, `dist`, `.next` (Postgres volume stays)  
3. Ensures `.env`, sources it, starts Docker Postgres/Redis and waits until healthy  
4. `pnpm install` → `db:generate` → build packages → `db:migrate` → `db:seed`  
5. Starts `pnpm dev`

Do **not** use `pnpm restart` — that is a reserved pnpm lifecycle (`stop` then `start`) and is not this script.

If Node 22 is not installed, the script warns and continues on the current Node.
